# Sprint Risk Prediction in Scrum

Research article project (Checkpoint 2 / Week 10: baseline and artifact
plan). See `docs/` for the proposal-level detail; this file is the
practical "how to run it" entry point.

**Research question** (from the Week 8 proposal): can pre-sprint,
planning-time features predict whether a Scrum sprint will be delayed or
spill scope, and which features matter most?

## Setup

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

## Run the baseline

```bash
python -m scripts.run_baseline
```

Loads the working dataset, builds both label variants, engineers
features, trains all three models under two validation schemes
(time-ordered per-project split, and leave-one-project-out), and writes
`results/baseline_results.json` plus two summary CSVs.

## Run the tests

```bash
pytest tests/ -v
# or, if pytest isn't installable in your environment:
python scripts/run_tests.py
```

## Current results (working baseline dataset, see docs/data_access_and_versioning.md)

Time-ordered split (train on each project's earlier sprints, test on its
later ones):

| Label | Model | Precision | Recall | F1 | ROC-AUC |
|---|---|---|---|---|---|
| delay | heuristic | 0.143 | 1.000 | 0.250 | – |
| delay | logistic regression | 0.160 | 0.400 | 0.229 | 0.403 |
| delay | random forest | 1.000 | 0.400 | 0.571 | 0.494 |
| spillover | heuristic | 0.900 | 0.969 | 0.933 | – |
| spillover | logistic regression | 0.932 | 0.846 | 0.887 | 0.723 |
| spillover | random forest | 0.912 | 0.954 | 0.932 | 0.747 |

Two things worth flagging honestly rather than glossing over:

1. **Spillover is near-universal in this dataset** (89% of sprints), not
   the minority-class problem the proposal expected. That's itself a
   finding worth discussing in the Week 12/14 write-up, and it's exactly
   the kind of label-definition sensitivity Section 6 (Threats to
   Validity) of the proposal flagged as a risk.
2. **Delay prediction is close to chance** (ROC-AUC ~0.40-0.49) on this
   dataset -- the planning-time features available here don't carry much
   signal about *delay* specifically, only about *spillover*. Whether
   that changes with TAWOS's larger, richer feature set (issue-level
   resolution timestamps, backlog-volatility flags) is an open question
   for the next checkpoint.

Full per-project (leave-one-project-out) numbers are in
`results/leave_one_project_out_summary.csv`.

## Moving to the full-scale dataset (TAWOS)

See `docs/data_access_and_versioning.md` -- short version: download TAWOS
on a network that can reach `rdr.ucl.ac.uk` (not this sandbox), export a
5-8 project subset with `scripts/export_tawos_subset.sql`, drop the CSVs
in `data/raw/tawos/`, and swap one import line in `scripts/run_baseline.py`.
